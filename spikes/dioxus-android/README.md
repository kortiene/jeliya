# Dioxus Android spike — issue #160

**Disposable.** This crate is not a root-workspace member, is not built by CI,
and is not the shape the real Android client should take. It exists only to
measure whether a Dioxus 0.7 system-WebView APK/AAB can carry Rust in-process,
use protected Android state, and survive representative physical-device flows.
Do not promote its v1 calls, JNI shape, package identifier, signing key, styles,
or UI into M2/M5 by assumption.

## Results

Ran on a physical device. Build, native runtime, IME, SAF, resume, rotation, and
predictive-Back rows pass. TalkBack is **partial**: the service and spoken TTS
were active, but next-item gestures outlined the system WebView as one node
instead of traversing its descendant heading, status, input, and button. The
UIAutomator accessibility tree contains those descendants; that is useful input,
not a substitute for successful TalkBack traversal.

| # | Criterion | Current result |
|---|---|---|
| 1 | Debug and release APK/AAB tasks succeed for selected ABI/device | **pass** — four artifacts built and inspected for `armeabi-v7a`; all carry development signatures. The debug APK uses Android's standard debug signer; debug AAB and both release-mode artifacts use the generated disposable signer. |
| 2 | Rust runs in-process with no Dart/FFI in spike path | **pass** — installed release loads `libjeliya_spike_160.so`; native evidence reports direct `jeliya-core`; target tree and dynamic symbols contain no `jeliya-ffi`/Dart entry point |
| 3 | Protected/no-backup test state | **pass, with inspection caveat** — native `noBackupFilesDir/dioxus-m0-spike-v1` is canonicalized and contains test marker/evidence files; manifest disables backup and both backup rule generations exclude all domains; `bmgr backupnow` reports `Backup is not allowed`. ## What the slice actually proves

`src/main.rs` depends directly on `../../crates/jeliya-core`. It starts one
bounded actor (`mpsc` capacity 8), awaits one `Engine::dispatch` at a time, and
makes seven bootstrap calls: status, identity create when needed, list/create
room, open room, status, and final list. `loopback=false` starts the real
network mode. The UI sees only display-safe facts.

This is a **v1 beachhead**, because v2 and the real DirectClient do not exist.
It is not the future typed API. There is deliberately no Dart VM, C ABI,
`jeliya-ffi`, WebSocket, daemon token, portfile, or fabricated reconnect. Resume
performs authoritative `room.list` and labels it resync, not reconnect.

Android Kotlin supplies exactly four platform hooks:

1. canonical no-backup directory + test marker; an existing unmarked directory
   is refused rather than adopted;
2. SAF `ACTION_OPEN_DOCUMENT` and a readable `content://` URI (never a fake
   path);
3. resume notification;
4. API-33 predictive Back callback.

The architecture record says the Android WebView floor is undecided. This spike
records the live versions (150.0.7871.46 initially, 150.0.7871.181 at the first
release run) as evidence only and does not invent a floor.

## Build

From this directory:

```sh
./build.sh all
./verify-artifacts.sh debug
./verify-artifacts.sh release
./check-native-graph.sh
./regressions.sh
```

`build.sh` exports the pinned SDK/NDK/JDK paths, generates a development-only
keystore plus unpredictable credentials under gitignored `.android/`, and
invokes:

```text
dioxus-dx bundle --android --target armv7-linux-androideabi \
  --package-types apk [--release]
# then generated Gradle: bundleDebug or bundleRelease, matching the Rust profile
```

Important Dioxus/Gradle assumptions discovered rather than guessed:

- `--package-types` must be repeated for multiple values; `--package-types apk
  aab` parses `aab` as a subcommand. More importantly, dx's AAB bundler always
  runs `bundleRelease`, even for a debug Rust build. `build.sh` therefore uses
  dx for the profile-correct APK/native build and explicitly runs Gradle
  `bundleDebug` or `bundleRelease` for the matching AAB. On this AGP 8.7
  project `bundleDebug` still emitted an unsigned AAB despite executing
  `signDebugBundle`; the script explicitly JAR-signs it with the same disposable
  key and verifies both bundles.
- dx 0.7.9 chooses a release APK only when the deprecated `[bundle.android]`
  signing block exists, and that block requires plaintext credentials.
  `[android.signing]` is documented but not consumed by this builder. Source
  stays credential-free: `build.sh` generates a mode-0600, gitignored
  `.android/signing.properties`, patches the generated Gradle project to read
  it, and explicitly runs `assembleRelease`/`bundleRelease`. Exact template
  anchors fail closed if dx changes.
- The custom activity must preserve
  `typealias BuildConfig = dev.jeliya.spike160.BuildConfig` for generated Wry
  Kotlin.
- R8 removes JNI-reflected Kotlin methods unless they are `@Keep`. The first
  installed release crashed with `NoSuchMethodError`; the build now asserts the
  methods remain in DEX.
- `prepareProtectedState` has two in-process callers on different threads
  (`onWebViewCreate` on the Android main thread and Rust `boot()` on a tokio
  worker through JNI). It is `@Synchronized` so create-then-verify is atomic; an
  unserialized version lets the losing caller of `mkdir()` throw "could not
  create protected state directory", which is an uncaught main-thread crash on
  the `onWebViewCreate` path. The captured device runs passed only because the
  two callers happened to serialize; the guard makes that deterministic.
- `launchSafPicker` runs `startActivityForResult` under `runOnUiThread` because
  the JNI call arrives on whatever thread Dioxus dispatches the click on;
  launching an activity-result flow off the main thread risks
  `CalledFromWrongThread`.
- dx has no custom `res/xml` hook. `build.rs` stages backup resources using
  dx's `WRY_ANDROID_KOTLIN_FILES_OUT_DIR`; `build.sh` also pre-stages them so a
  partially cleaned target tree cannot skip the copy through Cargo freshness.
- Dioxus's broad `lib` feature includes optional Manganis, which hard-errors on
  32-bit Android. The slice uses exact `minimal + document + mobile` features;
  it does not use Manganis assets.
- Dioxus 0.7.9 still generates AGP 8.7.0 with Gradle 9.1.0. It built here, but
  this nonstandard compatibility pairing is an M5 reproducibility input, not a
  recommendation.

The build assertions verify package ID, min/target SDK, `armeabi-v7a`, APK/AAB
signatures, native library entries, backup and predictive-Back manifest state,
retained JNI methods, and absence of retiring Flutter/FFI libraries. Gradle's
standard debug APK signer differs from the generated disposable signer used by
the debug AAB and release-mode artifacts; neither is distributable.

## Physical evidence

With exactly one authorized physical device, awake and unlocked:

```sh
./evidence.sh
```

The script refuses emulator signatures. It drives the real installed release
APK, waits for the `SPIKE160_NATIVE` line, checks process/crash state, captures
screenshots and accessibility hierarchy, exercises IME/resume/rotation, and
writes a gitignored timestamped directory under `evidence/`.

Retained redacted evidence lives under `evidence/final/`: portrait, IME,
landscape, SAF, TalkBack-focus screenshots; accessibility hierarchy; clean
uninstall/first-run facts; backup rejection; predictive-Back and TalkBack
traces; and checksums. Full logs and raw run directories remain gitignored.

Manual hardware observations:

1. **SAF pass.** Android DocumentsUI opened, Downloads showed the disposable
   37 B `jeliya-spike-160.txt`, the app read it and rendered `Picker: selected`,
   the display name, and a `content://` URI. It never treated the URI as a path,
   and logs retained only `SPIKE160_SAF status=selected`.
2. **Predictive Back pass after a real fix.** The first gesture entered Android
   `CoreBackPreview` but AppCompat consumed the callback, so the spike marker
   never fired. The activity now has one authority through
   `OnBackPressedDispatcher`; the rerun in gestural mode reported
   `TYPE_CALLBACK`, committed the gesture, and emitted `SPIKE160_BACK count=1`.
   Three-button navigation was restored afterward.
3. **TalkBack partial.** TalkBack bound with spoken/haptic/audible feedback,
   touch exploration, accessibility audio focus, and repeated Google TTS
   synthesis/dispatch while the spike remained foreground. Real next-item
   gestures left the green focus outline around the entire WebView, not the
   descendant nodes. Settings were restored to disabled.
4. **Visual pass for tested layouts.** Portrait, keyboard-resized, and landscape
   screenshots show the expected content without a blank WebView; landscape
   correctly reports an 822×387 viewport. This is one device, not a layout
   matrix.

Final release artifacts (development signer
`8a43af7ad0a46aae61dc58b1a3e5b12526d2b0fd3c81ce516f2a9a3860b30909`):

```text

AAB  7,628,105 bytes  6dc04001447174edd9938b9fcd115469fb4264d431a4c9c558f24956fae24d25
```

A true clean run uninstalled the disposable package (`Success`), installed the
final release APK, launched cold, created the marked state, and emitted the
seven-call first-run bootstrap:

```text
SPIKE160_PLATFORM_READY state=/data/data/dev.jeliya.spike160/no_backup/dioxus-m0-spike-v1 webview=150.0.7871.181
```

Physical bootstrap line from that release artifact:

```json
{"boundary":"jeliya-core direct","dart":false,"endpoint_id_reported":true,"ffi":false,"network_mode":"real","relay_observation":"engine reported no relay URL","serialized_calls":7,"test_data":true}
```

That is evidence of real-mode initialization and an endpoint, **not** evidence
of a relay session, direct peer path, background networking, or connectivity
while suspended. SELinux denied some route-netlink/sysfs discovery reads on
this Android 13 device; bootstrap still completed. M5 should decide whether
those denials reduce address/path observability in realistic peer tests.

## Deliberate regressions

Assertions that cannot fail are decoration. `./regressions.sh` mutates only
temporary artifact/evidence copies and requires each case to fail exactly one
named assertion. The retained matrix in `evidence/final/regressions.txt` passed:

| Regression | Only failing assertion |
|---|---|
| Alter one signed AAB payload while retaining entries/signature | AAB development signature |
| Remove only `base/res/xml/backup_rules.xml`, then re-sign | AAB full-backup exclusion resource |
| Add only `libjeliya_ffi.so`, then re-sign | no Flutter/jeliya-ffi library |
| Change native evidence `network_mode` to `loopback` | real network mode |
| Change native evidence `ffi` to `true` | no FFI |
| Change native evidence endpoint report to false | endpoint reported |
| Change clean-install serialized calls from seven to five | seven-call first-run path |
| Feed qemu/generic hardware observations to the device predicate | physical-device gate rejects them |

Two additional regressions were observed during development rather than
synthetically replayed: removing `@Keep` caused an installed release
`NoSuchMethodError`, and the first predictive-Back implementation entered the
OS gesture framework but never emitted the app callback marker. Both were fixed
and the final release DEX/device evidence asserts the corrected behavior.

## Negative and partial results

- This phone defaults to **three-button navigation** (`navigation_mode = 0`).
  Gestural mode was enabled temporarily for the real predictive-Back edge
  gesture and restored afterward.
- TalkBack was disabled initially and restored to disabled. Its service and TTS
  worked, but focus remained on the WebView as one node. Treat Android
  system-WebView descendant traversal as an M5 blocker/input, not as passed
  accessibility.
- The release package is intentionally non-debuggable. `run-as` cannot inspect
  private files. Protected placement is established by the platform-returned
  `noBackupFilesDir` path, canonical/native checks, marker reads/writes, and
  backup policy; a future M5 instrumentation build should independently inspect
  file location and backup extraction.
- Motorola's package clear/uninstall commands hung during one early evidence
  attempt. The final driver bounds clean uninstall at 120s and fails instead of
  falling back; the retained final clean run completed uninstall successfully.
- The first release run found and fixed an R8-only JNI removal bug. Debug-only
  evidence would have lied.
- A code audit (not the device, which passed by timing luck) found a race in
  `prepareProtectedState` between its main-thread and JNI-worker callers, and an
  off-main-thread `startActivityForResult` risk in `launchSafPicker`. Both are
  fixed (`@Synchronized`, `runOnUiThread`). Neither is falsifiable by a
  single-shot static assertion, so they are recorded here rather than added to
  the deliberate-regression table. The final clean-install and SAF runs exercise
  the fixed paths successfully.

## M5 findings

- **#190 (package/storage/ABI/signing)**: freeze the package namespace,
  `noBackupFilesDir`, both backup-rule generations, `armeabi-v7a` decision,
  JDK/SDK/NDK/Rust/dx/AGP/Gradle pins, upload-vs-development signing, and
  release DEX/JNI retention checks.
- **#191 (DirectClient/lifecycle)**: keep one bounded serialized actor, one
  owner, authoritative resume resync (never fabricated reconnect), deterministic
  teardown, and account for SELinux-limited network discovery.
- **#192 (SAF/platform services)**: retain real `content://` handling; never
  coerce a URI into a path; add bounded staging, cancel/denial, hostile metadata,
  revocation, cleanup, share, and export cases.
- **#193 (compact interaction)**: retain the one-authority predictive-Back fix,
  IME `adjustResize`, portrait/landscape recreation, safe areas, foreground
  refresh, focus, large-text, and phone/tablet layout rows.
- **#194 (qualification)**: make the TalkBack WebView descendant-traversal
  failure a tracked gate; record WebView/device/API/ABI/source SHA/digests; add
  direct/relay/NAT, process death, offline/resume, concurrent rooms, files, and
  Pipes across at least two physical API bands.

## What this does not prove

- Protocol v2, the future typed DirectClient, cross-adapter contract, or queue
  semantics beyond this disposable serialized beachhead.
- Relay/direct peer reachability, NAT behavior, long-running battery/background
  behavior, or resumed-room resync beyond `room.list`.
- Play Console acceptance, Play signing, reproducibility, upload key custody, or
  distributable signatures. Every artifact here uses a throwaway development
  key.
- Any supported Android/WebView floor, device matrix, accessibility
  certification, performance budget, or production UI quality.
